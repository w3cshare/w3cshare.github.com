项目配置脚本使用指南 ​

本文档介绍了 FullStack 项目中的配置脚本功能和使用方法。这些脚本主要用于自动化各子项目的配置文件初始化和管理工作，减少手动配置的重复劳动。

初始化配置脚本 (init-project-configs.js) ​

位置：_scripts/init-project-configs.js

功能描述 ​

该脚本会遍历项目中的各个子项目，执行以下操作：

  1. 如果子项目没有 package.json，创建一个基础版本
  2. 为子项目的 package.json 添加标准的 lint 和 format 脚本
  3. 复制或创建必要的配置文件（ESLint、Prettier、TypeScript 等）

智能检测特性 ​

脚本包含以下智能检测特性，避免不必要的文件创建：

  1. ESLint 配置智能检测：

    • 如果子项目根目录下已存在以下任一文件，将不再创建 eslint.config.mjs：
      • eslint.config.js
      • eslint.config.cjs
      • eslint.config.mjs
      • .eslintrc.js
    • 如果根目录下不存在 eslint.config.mjs 文件，会自动创建一个标准配置文件

  2. 自动生成配置文件：

    • 当子项目没有 .prettierrc 文件时，会自动创建最简配置文件
    • 当子项目没有 tsconfig.json 时，会自动创建一个基于项目规范的配置文件

使用方法 ​

bash
# 在项目根目录下执行
node _scripts/init-project-configs.js

README 生成脚本 (readme.js) ​

位置：_scripts/readme.js

功能描述 ​

该脚本用于为子项目生成符合 VitePress 文档规范的 README.md 文件，便于文档站点自动收集子项目信息。

  1. 遍历所有子项目目录
  2. 读取子项目的 package.json 获取名称和描述信息
  3. 为缺少 README.md 的子项目生成一个标准格式的文档

智能特性 ​

  • 优先使用 package.json 中的 displayName 字段作为项目标题
  • 如果不存在 displayName，则使用 name 字段
  • 为生成的 README 添加 VitePress 文档所需的 frontmatter

使用方法 ​

bash
# 在项目根目录下执行
node _scripts/readme.js
1
2

最佳实践 ​

  1. 在新增子项目后运行配置脚本：

    bash
    node _scripts/init-project-configs.js
node _scripts/readme.js
    1
    2

  2. 自定义配置文件：

    • 脚本仅在文件不存在时创建配置文件，不会覆盖已有配置
    • 可以根据子项目需求自由修改生成的配置文件

  3. TypeScript 继承关系：

    • 修改生成的 tsconfig.json 中的 references 字段，正确设置子项目依赖关系
    • 这对于 TypeScript 项目引用（Project References）功能至关重要

注意事项 ​

  1. 脚本执行需要 Node.js 环境
  2. 默认只处理特定目录（apps、lib-vue、lib-react 等），可通过修改脚本中的 DIRS_TO_PROCESS 数组添加其他目录
  3. ESLint 配置文件检测是智能的，会判断多种可能的配置文件格式
  4. 生成的 README.md 包含基础模板，建议根据实际项目情况进行完善
  5. 自动生成的 ESLint 配置使用 eslint-plugin-smart 插件，提供基础语法检查和 JSON 文件检查
  6. 自动生成的 Prettier 配置仅包含必要的插件引用，保持简洁易用
