Prettier 配置迁移 ​

迁移概述 ​

为了提高配置文件的一致性和兼容性，我们将所有子项目中的 .prettierrc 文件统一迁移到 .prettierrc.cjs 格式。此次迁移涉及到项目中所有使用 Prettier 配置的子项目。

迁移原因 ​

  1. CommonJS 兼容性：.cjs 扩展名明确表明文件使用 CommonJS 模块格式，增强了与各种工具的兼容性
  2. 统一配置规范：保持整个 Monorepo 项目中配置文件的一致性
  3. 避免解析问题：某些工具可能对 .prettierrc JSON 文件解析存在问题，而 .cjs 作为 JavaScript 文件更加灵活
  4. 支持动态配置：.cjs 格式允许使用 JavaScript 逻辑来动态生成配置，而不仅限于静态 JSON

迁移过程 ​

我们编写了一个自动化脚本 _scripts/replace-prettierrc.js 来完成这项工作：

  1. 使用 glob 查找所有包含 package.json 的子项目目录
  2. 在每个项目目录中：
    • 如果存在 .prettierrc 文件，则删除它并创建 .prettierrc.cjs
    • 如果不存在 .prettierrc 文件，则直接创建 .prettierrc.cjs
    • 如果已存在 .prettierrc.cjs 文件，则保留现有文件

.prettierrc.cjs 标准模板 ​

所有新创建的 .prettierrc.cjs 文件使用以下标准模板：

js
module.exports = {
  plugins: [require('prettier-plugin-smart')],
  ...require('prettier-plugin-smart').defaultOptions,
}

此配置引用了我们内部的 prettier-plugin-smart 插件，该插件提供了统一的代码格式化规则。

最佳实践 ​

  1. 新项目配置：所有新项目应直接使用 .prettierrc.cjs 而非 .prettierrc
  2. 插件依赖：确保项目依赖中包含 prettier-plugin-smart（通常在根 package.json 中已包含）
  3. 避免冲突：不要在子项目中重复定义与根项目冲突的 Prettier 规则
  4. 配置继承：优先使用配置继承而非复制粘贴完整配置

  3. 考虑将更多配置文件统一迁移到 .cjs 或其他标准化格式
