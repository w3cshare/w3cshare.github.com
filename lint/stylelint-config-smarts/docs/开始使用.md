# Stylelint 通用配置

stylelint-config-smarts 是一个企业级的 Stylelint 共享配置，提供了现代化且全面的 CSS 代码规范。适用于各种前端技术栈和框架，完美支持 React、Vue 和纯 TypeScript 项目。

## 为什么需要统一的样式规范？

在多人协作的前端项目中，统一的样式规范能够带来以下好处：

1. **提高代码可读性**：统一的格式使团队成员更容易理解彼此的代码
2. **减少样式冲突**：规范的属性顺序和命名方式减少潜在冲突
3. **加速开发效率**：自动化的代码格式化减少手动调整时间
4. **提升维护性**：规范化的代码更易于长期维护
5. **促进良好实践**：在整个团队中推广 CSS 的最佳实践

## 现代化特性

我们的配置采用了现代企业标准，提供以下特性：

- **现代 CSS 语法支持**：支持现代 CSS 函数表示法和语法
- **智能属性排序**：采用符合直觉和工程实践的属性排序系统
- **BEM 规范支持**：内置 BEM 编码规范检查
- **框架适配**：为 Vue、React 等框架提供专门配置
- **预处理器支持**：完美兼容 SCSS、Less 等预处理器

## 安装指南

### 依赖项

- Node.js >= 14
- stylelint >= 15.0.0

### 安装步骤

```bash
# 使用 pnpm 安装（推荐）
pnpm add -D stylelint stylelint-config-smarts

# 或使用 npm
npm install --save-dev stylelint stylelint-config-smarts

# 或使用 yarn
yarn add -D stylelint stylelint-config-smarts
```

## 基础配置

### 非 ESM 项目

在项目根目录创建 `.stylelintrc.js` 文件：

```js
module.exports = {
  extends: ['stylelint-config-smarts'],
  rules: {
    // 此处可添加项目特定的覆盖规则
  },
}
```

### ESM 项目

对于设置了 `"type": "module"` 的项目，创建 `.stylelintrc.cjs` 文件：

```js
module.exports = {
  extends: ['stylelint-config-smarts'],
  rules: {
    // 此处可添加项目特定的覆盖规则
  },
}
```

## 规则亮点

### 现代语法规则

- **颜色函数表示法**：`rgb(0 0 0 / 50%)` 而非 `rgba(0, 0, 0, 0.5)`
- **媒体查询语法**：使用传统 `min-width` 格式而非 `width >=` 格式，提高兼容性
- **HSL 色值**：使用明确的角度单位 `180deg` 而非 `180`
- **简化的十六进制颜色**：`#fff` 而非 `#ffffff`
- **百分比透明度**：`50%` 而非 `0.5`

### 智能属性排序

我们的属性排序系统遵循以下逻辑分组：

1. **定位** (position, z-index...)
2. **盒模型 - 布局** (display, flex, grid...)
3. **盒模型 - 尺寸** (width, height...)
4. **盒模型 - 外边距** (margin...)
5. **盒模型 - 内边距** (padding...)
6. **盒模型 - 边框** (border...)
7. **视觉效果** (background, opacity...)
8. **文本与字体** (font, color...)
9. **动画与过渡** (transition, animation...)
10. **其他** (cursor, user-select...)

### BEM 编码规范

内置 BEM 规范检查包括：

- 绝对定位元素需要至少指定两个方向
- 动画必须包含明确的时间函数
- 避免使用 inline 相关的 display 值
- 防止媒体查询中的冗余属性值
- 避免在 BEM 修饰符中重复已有的属性值

## 与构建工具集成

### Vite 集成

安装 `vite-plugin-stylelint`：

```bash
pnpm add -D vite-plugin-stylelint
```

在 `vite.config.js` 中配置：

```js
import { defineConfig } from 'vite'
import stylelint from 'vite-plugin-stylelint'

export default defineConfig({
  plugins: [
    stylelint({
      fix: true, // 自动修复
      cache: true, // 启用缓存
      lintOnStart: false, // 启动时不立即检查
    }),
  ],
})
```

### Webpack 集成

安装 `stylelint-webpack-plugin`：

```bash
pnpm add -D stylelint-webpack-plugin
```

在 webpack 配置中添加：

```js
const StylelintPlugin = require('stylelint-webpack-plugin')

module.exports = {
  // ...其他配置
  plugins: [
    new StylelintPlugin({
      fix: true, // 自动修复
      cache: true, // 启用缓存
      files: ['**/*.{css,scss,less,vue}'],
      configBasedir: __dirname, // 配置文件的基础目录
    }),
  ],
}
```

## 命令行使用

在 `package.json` 中添加脚本命令：

```json
{
  "scripts": {
    "lint:style": "stylelint \"**/*.{css,scss,less,vue}\" --fix",
    "lint:style:check": "stylelint \"**/*.{css,scss,less,vue}\""
  }
}
```

对于 ESM 项目，需要明确指定配置文件：

```json
{
  "scripts": {
    "lint:style": "stylelint \"**/*.{css,scss,less,vue}\" --fix --config .stylelintrc.cjs",
    "lint:style:check": "stylelint \"**/*.{css,scss,less,vue}\" --config .stylelintrc.cjs"
  }
}
```

## 与 IDE 集成

### VS Code

安装 [Stylelint 扩展](https://marketplace.visualstudio.com/items?itemName=stylelint.vscode-stylelint) 并配置：

```json
{
  "stylelint.validate": ["css", "scss", "less", "vue"],
  "editor.codeActionsOnSave": {
    "source.fixAll.stylelint": true
  },
  "css.validate": false,
  "less.validate": false,
  "scss.validate": false
}
```

## 常见问题

### 1. 与 Prettier 冲突

stylelint-config-smarts 已包含 `stylelint-config-prettier` 以避免与 Prettier 冲突。如仍有冲突，请确保 Prettier 在 Stylelint 之后运行。

### 2. 规则太严格怎么办？

可在项目配置中禁用特定规则：

```js
module.exports = {
  extends: ['stylelint-config-smarts'],
  rules: {
    'max-nesting-depth': null, // 禁用嵌套深度限制
    'selector-max-compound-selectors': null, // 禁用复合选择器数量限制
    'color-function-notation': 'legacy', // 使用传统颜色函数表示法
  },
}
```

### 3. VS Code 插件冲突

如遇到 VS Code 插件冲突，可更新 settings.json：

```json
{
  "stylelint.validate": ["css", "scss", "less", "vue"],
  "css.validate": false,
  "less.validate": false,
  "scss.validate": false
}
```

### 4. ES Module 项目中的配置问题

在使用 ESM 格式的项目中（package.json 中设置了 `"type": "module"`），Stylelint 配置需要特别注意：

#### 4.1 配置文件使用 .cjs 扩展名

为避免 ES Module 加载问题，应使用 `.stylelintrc.cjs` 而非 `.stylelintrc.js`：

```js
// .stylelintrc.cjs
module.exports = {
  extends: ['stylelint-config-smarts'],
  // ... 其他配置
}
```

#### 4.2 明确指定配置文件

在命令行或 package.json 脚本中明确指定配置文件：

```json
{
  "scripts": {
    "lint:style": "stylelint \"**/*.{css,scss,less,vue}\" --config .stylelintrc.cjs"
  }
}
```

#### 4.3 插件兼容性问题

当使用插件时，可能出现版本兼容性问题。解决方案：

1. 明确声明插件并禁用可能不兼容的规则：

```js
// .stylelintrc.cjs
module.exports = {
  extends: ['stylelint-config-smarts'],
  rules: {
    // 禁用不兼容的规则
    'bem-newbie/absolute-has-two-dimensions': null,
    // 其他规则...
  }
}
```

2. 考虑调整 Stylelint 或插件版本以解决兼容性问题
