# Stylelint 通用配置

stylelint-config-smarts 是一个专为公司内部项目设计的 Stylelint 共享配置，提供了统一且智能的 CSS 代码规范。适用于各种前端技术栈，包括 React、Vue 和纯 TypeScript 项目。

## 为什么需要统一的样式规范？

在多人协作的前端项目中，统一的样式规范能够带来以下好处：

1. **提高代码可读性**：统一的格式使团队成员更容易理解彼此的代码
2. **减少样式冲突**：规范的属性顺序和命名方式减少潜在冲突
3. **加速开发效率**：自动化的代码格式化减少手动调整时间
4. **提升维护性**：规范化的代码更易于长期维护
5. **促进良好实践**：在整个团队中推广 CSS 的最佳实践

## 安装指南

### 依赖项

- Node.js >= 14
- stylelint >= 15.0.0

### 安装步骤

```bash
# 使用 pnpm 安装（推荐）
pnpm add -D stylelint stylelint-config-smarts

# 或使用 npm
npm install --save-dev stylelint stylelint-config-smarts

# 或使用 yarn
yarn add -D stylelint stylelint-config-smarts
```

## 基础配置

在项目根目录创建 `.stylelintrc.js` 文件：

```js
module.exports = {
  extends: ['stylelint-config-smarts'],
  rules: {
    // 此处可添加项目特定的覆盖规则
  }
};
```

## 与构建工具集成

### Vite 集成

安装 `vite-plugin-stylelint`：

```bash
pnpm add -D vite-plugin-stylelint
```

在 `vite.config.js` 中配置：

```js
import { defineConfig } from 'vite';
import stylelint from 'vite-plugin-stylelint';

export default defineConfig({
  plugins: [
    stylelint({
      fix: true, // 自动修复
      cache: true // 启用缓存
    })
  ]
});
```

### Webpack 集成

安装 `stylelint-webpack-plugin`：

```bash
pnpm add -D stylelint-webpack-plugin
```

在 webpack 配置中添加：

```js
const StylelintPlugin = require('stylelint-webpack-plugin');

module.exports = {
  // ...其他配置
  plugins: [
    new StylelintPlugin({
      fix: true, // 自动修复
      cache: true, // 启用缓存
      files: ['**/*.{css,scss,less,vue}']
    })
  ]
};
```

### 与 Ant Design 项目集成

Ant Design 项目中通常使用 Less 作为预处理器。stylelint-config-smarts 已包含必要的规则，可以直接使用：

```js
// .stylelintrc.js
module.exports = {
  extends: ['stylelint-config-smarts'],
  rules: {
    // Ant Design 特有的变量命名规则
    'scss/dollar-variable-pattern': null,
    // 其他 Ant Design 特有规则
  }
};
```

## 命令行使用

在 `package.json` 中添加脚本命令：

```json
{
  "scripts": {
    "lint:style": "stylelint \"**/*.{css,scss,less,vue}\"",
    "lint:style:fix": "stylelint \"**/*.{css,scss,less,vue}\" --fix"
  }
}
```

运行 lint 检查：

```bash
pnpm run lint:style
```

运行 lint 并自动修复：

```bash
pnpm run lint:style:fix
```

## 提交前检查

结合 husky 和 lint-staged 在提交前自动检查样式：

```bash
pnpm add -D husky lint-staged
```

在 `package.json` 中配置：

```json
{
  "husky": {
    "hooks": {
      "pre-commit": "lint-staged"
    }
  },
  "lint-staged": {
    "*.{css,scss,less,vue}": [
      "stylelint --fix",
      "git add"
    ]
  }
}
```

## 常见问题

### 1. 与 Prettier 冲突

stylelint-config-smarts 已包含 `stylelint-config-prettier` 以避免与 Prettier 冲突。如仍有冲突，请确保 Prettier 在 Stylelint 之后运行。

### 2. 规则太严格怎么办？

可在项目配置中禁用特定规则：

```js
module.exports = {
  extends: ['stylelint-config-smarts'],
  rules: {
    'max-nesting-depth': null, // 禁用嵌套深度限制
    'selector-max-compound-selectors': null // 禁用复合选择器数量限制
  }
};
```

### 3. VS Code 插件冲突

如遇到 VS Code 插件冲突，可更新 settings.json：

```json
{
  "stylelint.validate": ["css", "scss", "less", "vue"],
  "css.validate": false,
  "less.validate": false,
  "scss.validate": false
}
```
