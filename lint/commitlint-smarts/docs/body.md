# 提交消息正文指南

提交消息正文是提交主题行之后的详细说明部分，用于提供更多关于变更的详细信息。虽然不是所有提交都需要正文，但对于重要或复杂的变更，正文是必不可少的。

## 正文的位置

在提交消息格式中，正文位于主题行之后，中间空一行：

```
<type>(<scope>): <subject>

<body>

<footer>
```

## 何时使用正文

以下情况建议使用正文：

1. **复杂变更**：实现了复杂的功能或修复了复杂的问题
2. **重大改动**：包含破坏性变更（Breaking Changes）
3. **设计决策**：需要解释为什么选择了特定实现方法
4. **多方面变更**：一次提交包含多个相关联的变更
5. **复杂问题修复**：修复了难以理解或重现的bug

## 正文的格式规范

### 基本规则

1. **使用空行分隔段落**：增加可读性
2. **每行限制72个字符**：确保在各种终端和工具中正确显示
3. **使用完整句子**：包含主语、谓语和宾语
4. **使用祈使句**：与主题行保持一致的语气
5. **提供上下文**：解释变更的背景和原因

### 中文正文规范

对于使用中文的项目，正文应遵循以下额外规范：

1. **简体中文**：统一使用简体中文
2. **避免使用缩写**：除非是广泛接受的技术缩写
3. **保持标点符号一致**：统一使用中文或英文标点
4. **段落结构清晰**：可使用项目符号或数字列表增强可读性

## 正文内容指南

一个完整的提交消息正文应回答以下问题：

1. **为什么需要这个变更？**
2. **它如何解决问题？**
3. **这个变更对系统有什么影响？**
4. **有哪些需要注意的限制或边界条件？**
5. **相关的问题或任务编号是什么？**

## 有效的正文示例

### 功能添加示例

```
feat(auth): 添加谷歌OAuth登录功能

实现了基于OAuth 2.0协议的谷歌账号登录功能，使用户可以通过谷歌账号快速注册和登录系统。

主要包括：
1. 集成谷歌OAuth 2.0 API
2. 添加授权回调处理
3. 用户信息自动关联和账号创建
4. 权限验证和令牌刷新机制

该功能大幅简化了用户注册流程，预计可提高注册转化率约15%。

相关任务: #TASK-123
```

### 问题修复示例

```
fix(database): 修复高并发下连接池耗尽问题

在高并发场景下，数据库连接未能正确释放，导致连接池资源耗尽，系统响应变慢并最终超时。

问题原因：
- 事务提交后连接未正确关闭
- 异常处理路径中缺少连接释放代码
- 连接池配置不合理

解决方法：
1. 添加try-finally确保连接总是被释放
2. 调整连接池大小和超时设置
3. 增加连接泄漏检测和自动回收机制

性能测试显示该修复在高峰期将系统响应时间从2.5s降至0.8s。

修复: #BUG-456
```

## 特殊部分指南

### 列表格式

使用列表时，保持一致的格式：

```
本次重构包括以下改进：

1. 拆分大型控制器为多个更小的类
2. 引入中间件处理通用逻辑
3. 优化数据库查询减少IO操作
4. 添加单元测试提高覆盖率
```

### 引用相关资源

在正文中引用相关资源：

```
详细设计文档：https://wiki.company.com/design/feature-x
性能测试报告：https://metrics.company.com/report/123
相关讨论：#PR-789
```

## 自动化配置

您可以在`commitlint.config.js`中配置对正文的检查：

```js
module.exports = {
  extends: ['@company/commitlint-smarts'],
  rules: {
    'body-leading-blank': [2, 'always'],
    'body-max-line-length': [2, 'always', 72],
    'body-case': [0, 'always', 'lowerCase']
  }
};
```

## 小结

一个好的提交消息正文：
- 解释变更的原因和影响
- 提供足够的上下文理解变更
- 记录重要的设计决策
- 链接相关资源和参考信息
- 帮助未来的开发者理解代码演化历史

记住：编写详细的提交消息正文是对未来自己和团队成员的尊重，它将在代码审查、故障排除和功能理解方面节省宝贵的时间。
