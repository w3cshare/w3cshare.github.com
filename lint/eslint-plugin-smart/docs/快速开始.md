# eslint-plugin-smart 快速开始

::: tip 插件介绍
eslint-plugin-smart 是一个为公司内部项目设计的 ESLint 规则集合，提供了针对 JavaScript、TypeScript、React、Vue 和 NestJS 等多种技术栈的全面规则配置。
:::

## 快速开始

### 安装

根据您使用的包管理器选择相应的安装命令：

::: code-group

```bash [pnpm]
# 使用 pnpm (推荐)
pnpm add -D eslint eslint-plugin-smart
```

```bash [npm]
# 使用 npm
npm install --save-dev eslint eslint-plugin-smart
```

```bash [yarn]
# 使用 yarn
yarn add --dev eslint eslint-plugin-smart
```

:::

### 基础配置

::: code-group

```js [ESLint v9+ (扁平配置)]
// eslint.config.mjs
import eslintPlugin from 'eslint-plugin-smart';

// 注意：配置是一个数组，需要展开
export default [
  ...eslintPlugin.configs.recommended,
  {
    // 这里可以添加自定义规则
  },
];
```

```js [ESLint v8 及以下]
// .eslintrc.js
module.exports = {
  extends: ['plugin:smart/recommended'],
};
```

:::

## 规则说明

eslint-plugin-smart 提供了多种预设配置，根据项目类型可选择不同的配置集合：

| 预设配置            | 说明            | 适用场景                   |
| ------------------- | --------------- | -------------------------- |
| `smart/recommended` | 基础推荐配置    | 适用于所有 JavaScript 项目 |
| `smart/typescript`  | TypeScript 配置 | 适用于 TypeScript 项目     |
| `smart/react`       | React 配置      | 适用于 React 项目          |
| `smart/vue`         | Vue 配置        | 适用于 Vue 项目            |
| `smart/nestjs`      | NestJS 配置     | 适用于 NestJS 后端项目     |

### 基础规则

以下是 `smart/recommended` 配置中包含的部分基础规则：

::: details 代码风格规则
| 规则 | 说明 | 严重级别 |
|-----|------|---------|
| `indent` | 使用一致的缩进（默认为2空格） | 错误 |
| `quotes` | 使用一致的引号风格（默认为单引号） | 错误 |
| `semi` | 要求或禁止使用分号 | 错误 |
| `no-unused-vars` | 禁止出现未使用过的变量 | 警告 |
| `comma-dangle` | 要求或禁止末尾逗号 | 警告 |
| `arrow-parens` | 箭头函数参数括号风格 | 警告 |
| `max-len` | 强制行的最大长度 | 警告 |
| `eol-last` | 要求或禁止文件末尾保留一行空行 | 错误 |
:::

::: details 代码质量规则
| 规则 | 说明 | 严重级别 |
|-----|------|---------|
| `no-console` | 禁用 console 方法 | 警告 |
| `no-debugger` | 禁用 debugger | 错误 |
| `no-alert` | 禁用 alert、confirm 和 prompt | 错误 |
| `no-eval` | 禁用 eval() | 错误 |
| `no-implied-eval` | 禁止使用类似 eval() 的方法 | 错误 |
| `no-new-func` | 禁止对 Function 对象使用 new 操作符 | 错误 |
| `no-return-assign` | 禁止在 return 语句中使用赋值语句 | 错误 |
| `no-prototype-builtins` | 禁止直接使用 Object.prototypes 的内置属性 | 错误 |
| `curly` | 强制所有控制语句使用一致的括号风格 | 错误 |
:::

::: details 导入/导出规则
| 规则 | 说明 | 严重级别 |
|-----|------|---------|
| `import/order` | 强制导入的排序 | 警告 |
| `import/first` | 确保所有导入都在文件顶部 | 错误 |
| `import/no-mutable-exports` | 禁止导出可变的绑定 | 错误 |
| `import/no-unresolved` | 确保导入的模块可以被解析 | 错误 |
| `import/no-webpack-loader-syntax` | 禁止在导入中使用 Webpack 加载器语法 | 错误 |

## 配置指南

### 使用内置插件

eslint-plugin-smart 已经内置了常用的 ESLint 插件，无需在项目中单独安装。以下是如何使用这些内置插件的方法：

#### 在 ESLint v9+ 中使用内置插件

```js
// eslint.config.mjs
import eslintPlugin from 'eslint-plugin-smart';

export default [
  // 使用预设配置（注意：配置是数组，需要展开）
  ...eslintPlugin.configs.recommended,
  
  // 或者，手动配置并使用内置插件
  {
    plugins: {
      // 使用内置插件
      'import': eslintPlugin.plugins.import,
      'simple-import-sort': eslintPlugin.plugins['simple-import-sort'],
      'unused-imports': eslintPlugin.plugins['unused-imports'],
    },
    rules: {
      // 使用插件规则
      'simple-import-sort/imports': 'error',
      'simple-import-sort/exports': 'error',
      'unused-imports/no-unused-imports': 'error',
      // 其他规则...
    }
  }
];
```

#### 在 ESLint v8 中使用内置插件

对于 ESLint v8 及以下版本，当你使用 `extends: ['plugin:smart/recommended']` 时，插件会自动注册并启用相关规则，无需额外配置。

### 内置插件列表

`eslint-plugin-smart` 内置了以下插件：

::: details 内置插件
- `eslint-plugin-import` - 导入/导出语法检查
- `eslint-plugin-simple-import-sort` - 导入排序
- `eslint-plugin-unused-imports` - 自动移除未使用的导入
- `@typescript-eslint/eslint-plugin` 和 `@typescript-eslint/parser` - TypeScript支持
- `eslint-plugin-react` 和 `eslint-plugin-react-hooks` - React支持
- `eslint-plugin-jsx-a11y` - React可访问性支持
- `eslint-plugin-vue` 和 `vue-eslint-parser` - Vue支持
- `eslint-plugin-node` - Node.js和NestJS支持
:::

### 自定义规则配置

您可以通过在配置文件中扩展预设配置并覆盖规则来自定义 ESLint 行为：

#### 在 ESLint v9+ 中 (扁平配置系统)

```js
// eslint.config.mjs
import eslintPlugin from 'eslint-plugin-smart';

export default [
  // 使用预设配置
  ...eslintPlugin.configs.recommended,
  // 自定义配置
  {
    rules: {
      // 覆盖现有规则
      'no-console': 'error', // 将警告升级为错误
      'max-len': ['warn', { code: 100 }], // 修改行长度限制为100
      
      // 关闭不需要的规则
      'no-unused-vars': 'off',
      
      // 添加其他规则
      'prefer-const': 'error', // 优先使用const
    }
  }
];
```

#### 在 ESLint v8 及以下版本中

```js
// .eslintrc.js
module.exports = {
  extends: ['plugin:smart/recommended'],
  rules: {
    // 覆盖现有规则
    'no-console': 'error',
    'max-len': ['warn', { code: 100 }],
    
    // 关闭不需要的规则
    'no-unused-vars': 'off',
    
    // 添加其他规则
    'prefer-const': 'error',
  },
};
```

### 规则严重性级别

ESLint 规则可以有三种严重性级别：

::: tip 规则级别
- `"off"` 或 `0` - 关闭规则
- `"warn"` 或 `1` - 将规则视为警告（不会导致退出代码非零）
- `"error"` 或 `2` - 将规则视为错误（退出代码为1，触发时）
:::

### Monorepo 项目配置

对于单体仓库项目，可以采用以下配置方式：

::: code-group
```js [ESLint v9+]
// 根目录 eslint.config.mjs
import eslintPlugin from 'eslint-plugin-smart';

// 创建基础配置
const baseConfig = [
  ...eslintPlugin.configs.recommended,
  {
    rules: {
      // 所有包共享的规则
    }
  }
];

export default baseConfig;

// 导出不同类型的配置供子包使用
export const tsConfig = [
  ...eslintPlugin.configs.typescript,
];

export const reactConfig = [
  ...eslintPlugin.configs.typescript,
  ...eslintPlugin.configs.react,
];

export const vueConfig = [
  ...eslintPlugin.configs.typescript,
  ...eslintPlugin.configs.vue,
];
```

```js [ESLint v8 及以下]
// 根目录 .eslintrc.js
module.exports = {
  root: true,
  extends: ['plugin:smart/recommended'],
  rules: {
    // 共享规则
  },
};
```
:::

在子包中引用配置：

::: code-group
```js [ESLint v9+]
// packages/my-package/eslint.config.mjs
import { reactConfig } from '../../eslint.config.mjs';

export default [
  ...reactConfig,
  {
    // 子包特定规则
  }
];
```

```js [ESLint v8 及以下]
// packages/my-package/.eslintrc.js
module.exports = {
  extends: [
    '../../.eslintrc.js',
    'plugin:smart/react',
  ],
  rules: {
    // 子包特定规则
  },
};
```
:::


## ESLint v9 支持

ESLint v9 引入了扁平配置系统，与之前版本的配置方式有较大差异。我们的插件已经完全兼容 ESLint v9，同时保持向下兼容。

### 配置系统的变化

ESLint v9 的主要变化包括：

1. 配置文件从 `.eslintrc.js` 改为 `eslint.config.mjs` 或 `eslint.config.js`
2. 不再使用 `extends` 字段，而是直接使用数组包含配置对象
3. 引入了 `languageOptions` 和 `files` 等新字段
4. 插件需要使用 `plugins` 对象显式导入

### 注意事项

::: warning 重要提示
1. **预设配置是数组**：在 ESLint v9 中，插件的预设配置是一个数组，使用时需要展开：

```js
// 正确用法
export default [...eslintPlugin.configs.typescript];

// 错误用法
export default eslintPlugin.configs.typescript;
```

2. **TypeScript 版本兼容性**：注意检查 TypeScript 和 @typescript-eslint 的版本兼容性。
:::

```json
    "vue"
```

1. 确保启用了 ESLint 插件（通常默认已启用）
2. 进入 `Settings` > `Languages & Frameworks` > `JavaScript` > `Code Quality Tools` > `ESLint`
3. 启用 ESLint 并配置适当的设置

## 在项目中运行 ESLint

在 `package.json` 中添加以下脚本：

```json
{
  "scripts": {
    "lint": "eslint . --ext .js,.jsx,.ts,.tsx,.vue",
    "lint:fix": "eslint . --ext .js,.jsx,.ts,.tsx,.vue --fix"
  }
}
```

然后，您可以使用以下命令运行 ESLint：

```bash
# 检查代码
pnpm run lint

# 检查并自动修复问题
pnpm run lint:fix
```

## 使用示例

### 完整项目示例

以下是一个完整的 React + TypeScript 项目的 ESLint 配置示例：

```js
// eslint.config.mjs
import eslintPlugin from 'eslint-plugin-smart';

export default [
  ...eslintPlugin.configs.typescript,
  ...eslintPlugin.configs.react,
  {
    files: ['**/*.{ts,tsx}'],
    rules: {
      // 自定义调整
      '@typescript-eslint/explicit-function-return-type': 'warn',
      'react/prop-types': 'off', // 使用 TypeScript 类型时不需要 prop-types
      'max-len': ['warn', { code: 100, ignoreStrings: true }],
    },
  },
  // 针对测试文件的特殊规则
  {
    files: ['**/*.test.{ts,tsx}', '**/*.spec.{ts,tsx}'],
    rules: {
      '@typescript-eslint/no-explicit-any': 'off',
      'max-len': 'off',
    },
  },
];
```

### 针对不同文件类型的配置

## 常见问题解答

::: details 规则冲突问题
**问题**: 我的项目中使用了其他 ESLint 配置，与 eslint-plugin-smart 产生了规则冲突。

**解决方案**: 可以覆盖特定规则来解决冲突：

```js
// eslint.config.mjs
export default [
  ...eslintPlugin.configs.recommended,
  {
    rules: {
      // 覆盖冲突的规则
      'conflicting-rule': 'off',
    },
  },
];
```
:::

::: details Prettier 集成问题
**问题**: 我想将 eslint-plugin-smart 与 Prettier 一起使用。

**解决方案**: eslint-plugin-smart 默认已考虑与 Prettier 的兼容性。如果仍有冲突，可以添加 eslint-config-prettier：

```js
// eslint.config.mjs
import eslintPlugin from 'eslint-plugin-smart';
import prettier from 'eslint-config-prettier';

export default [
  ...eslintPlugin.configs.recommended,
  prettier, // 放在最后以覆盖可能冲突的规则
];
```
:::

::: details 规则过于严格
**问题**: 某些规则对我的项目来说过于严格。

**解决方案**: 可以将规则级别从 "error" 降级为 "warn" 或完全禁用：

```js
export default [
  ...eslintPlugin.configs.recommended,
  {
    rules: {
      'no-console': 'warn', // 降级为警告
      'max-len': 'off',     // 完全禁用
    },
  },
];
```
:::

- 减少配置时间，专注于开发
- 确保代码质量和风格一致性
- 支持多种技术栈和项目类型

无论是新项目还是现有项目，eslint-plugin-smart 都能帮助您提高代码质量和团队协作效率。
