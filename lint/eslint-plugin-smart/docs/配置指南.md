# 配置指南

本文档详细介绍了如何根据项目需求自定义 eslint-plugin-smart 的配置。

## 基本配置修改

您可以通过在配置文件中扩展预设配置并覆盖规则来自定义 ESLint 行为：

### 在 ESLint v9+ 中

```js
// eslint.config.js
export default {
  extends: ['plugin:smart/recommended'],
  rules: {
    // 覆盖现有规则
    'no-console': 'error', // 将警告升级为错误
    'max-len': ['warn', { code: 100 }], // 修改行长度限制为100
    
    // 关闭不需要的规则
    'no-unused-vars': 'off',
    
    // 添加其他规则
    'prefer-const': 'error', // 优先使用const
  },
};
```

### 在 ESLint v8 及以下版本中

```js
// .eslintrc.js
module.exports = {
  extends: ['plugin:smart/recommended'],
  rules: {
    // 覆盖现有规则
    'no-console': 'error',
    'max-len': ['warn', { code: 100 }],
    
    // 关闭不需要的规则
    'no-unused-vars': 'off',
    
    // 添加其他规则
    'prefer-const': 'error',
  },
};
```

## 规则严重性级别

ESLint 规则可以有三种严重性级别：

- `"off"` 或 `0` - 关闭规则
- `"warn"` 或 `1` - 将规则视为警告（不会导致退出代码非零）
- `"error"` 或 `2` - 将规则视为错误（退出代码为1，触发时）

## 组合多个配置

您可以组合多个预设配置以满足特定项目的需求：

```js
// eslint.config.js (ESLint v9+)
export default {
  extends: [
    'plugin:smart/typescript', // 基础TypeScript规则
    'plugin:smart/react',      // React规则
  ],
  rules: {
    // 自定义规则...
  },
};

// .eslintrc.js (ESLint v8 及以下)
module.exports = {
  extends: [
    'plugin:smart/typescript',
    'plugin:smart/react',
  ],
  rules: {
    // 自定义规则...
  },
};
```

## 项目特定配置

### Monorepo 项目

对于单体仓库项目，您可以在根目录设置基础配置，并在各个包中进行扩展：

#### 根目录配置

```js
// 根目录 .eslintrc.js
module.exports = {
  extends: ['plugin:smart/recommended'],
  rules: {
    // 所有包共享的规则
  },
};
```

#### 包特定配置

```js
// packages/my-package/.eslintrc.js
module.exports = {
  extends: ['../../.eslintrc.js', 'plugin:smart/react'],
  rules: {
    // 包特定规则
  },
};
```

### 针对特定文件的配置

您可以针对特定文件或目录应用不同的规则：

```js
// .eslintrc.js
module.exports = {
  extends: ['plugin:smart/recommended'],
  rules: {
    // 基础规则
  },
  overrides: [
    {
      files: ['*.test.js', '*.spec.js'],
      rules: {
        // 针对测试文件的规则
        'no-unused-expressions': 'off',
      },
    },
    {
      files: ['scripts/**/*.js'],
      rules: {
        // 针对脚本的规则
        'no-console': 'off',
      },
    },
  ],
};
```

## 环境配置

您可以指定代码运行的环境，这会预定义一些全局变量：

```js
// .eslintrc.js
module.exports = {
  extends: ['plugin:smart/recommended'],
  env: {
    browser: true, // 浏览器环境
    node: true,    // Node.js 环境
    jest: true,    // Jest 测试环境
    es2021: true,  // 添加所有 ECMAScript 2021 的全局变量
  },
  rules: {
    // 规则...
  },
};
```

## 解析器选项

您可以自定义解析器选项以支持特定的语言特性：

```js
// .eslintrc.js
module.exports = {
  extends: ['plugin:smart/typescript'],
  parserOptions: {
    ecmaVersion: 2021,    // 使用 ECMAScript 2021 语法
    sourceType: 'module', // 使用 ECMAScript 模块
    ecmaFeatures: {
      jsx: true,          // 启用 JSX
    },
    project: './tsconfig.json', // TypeScript 项目配置文件
  },
  rules: {
    // 规则...
  },
};
```

## 与 Prettier 集成

eslint-plugin-smart 可以与 Prettier 代码格式化工具集成：

```bash
# 安装依赖
pnpm add -D prettier eslint-config-prettier eslint-plugin-prettier
```

然后更新您的 ESLint 配置：

```js
// .eslintrc.js
module.exports = {
  extends: [
    'plugin:smart/recommended',
    'plugin:prettier/recommended', // 启用 prettier 并关闭与其冲突的 ESLint 规则
  ],
  rules: {
    // 其他规则...
  },
};
```

## 忽略特定文件

您可以在项目根目录创建 `.eslintignore` 文件来忽略特定文件或目录：

```
# .eslintignore
dist/
node_modules/
coverage/
build/
*.min.js
```

## 内联禁用规则

在特定情况下，您可以直接在代码中禁用特定规则：

```js
// 禁用整个文件的特定规则
/* eslint-disable no-console */

console.log('禁用了no-console规则');

// 重新启用规则
/* eslint-enable no-console */

// 仅禁用下一行的规则
// eslint-disable-next-line no-alert
alert('禁用了no-alert规则');

// 禁用特定代码块的规则
/* eslint-disable no-console, no-alert */
console.log('这里可以使用console');
alert('这里可以使用alert');
/* eslint-enable no-console, no-alert */
```

## 定制共享配置

对于大型组织，您可以创建自己的共享 ESLint 配置：

1. 创建一个名为 `eslint-config-your-org` 的包
2. 在包中导出配置：

```js
// index.js
module.exports = {
  extends: ['plugin:smart/recommended'],
  rules: {
    // 组织特定规则
  },
};
```

3. 在项目中使用您的配置：

```js
// .eslintrc.js
module.exports = {
  extends: ['your-org'],
  rules: {
    // 项目特定规则
  },
};
```

## 故障排除

### 解决规则冲突

如果您遇到规则冲突，请确保将可能冲突的配置放在 `extends` 数组的最后，这样它可以覆盖之前的配置。

### 性能优化

对于大型项目，ESLint 可能会变慢。以下是一些提高性能的技巧：

1. 使用 `.eslintignore` 忽略不需要检查的文件
2. 使用 `--cache` 标志启用缓存
3. 仅检查修改的文件
4. 考虑使用 `eslint-webpack-plugin` 或 `@typescript-eslint/eslint-plugin` 的性能优化选项
