# Lint

eslint-plugin-smart 提供了一套全面的 ESLint 规则集合，旨在提高项目代码质量和一致性。本文档详细介绍了插件中包含的规则及其分类。

* [🔧 规则配置方法](#规则配置方法)
* [🌚 临时禁用规则](#临时禁用规则)

## 📏 规则列表

eslint-plugin-smart 提供了多种预设配置，根据项目类型可选择不同的配置集合：

| 预设配置            | 说明            | 适用场景                   |
| ------------------- | --------------- | -------------------------- |
| `smart/recommended` | 基础推荐配置    | 适用于所有 JavaScript 项目 |
| `smart/typescript`  | TypeScript 配置 | 适用于 TypeScript 项目     |
| `smart/react`       | React 配置      | 适用于 React 项目          |
| `smart/vue`         | Vue 配置        | 适用于 Vue 项目            |
| `smart/nestjs`      | NestJS 配置     | 适用于 NestJS 后端项目     |

### 代码风格规则

代码风格规则确保项目中代码格式的一致性，提高可读性和维护性。

| 规则 | 说明 | 严重级别 | 是否自动修复 |
|-----|------|---------|-------------|
| `indent` | 使用一致的缩进（默认为2空格） | 错误 | ✅ |
| `quotes` | 使用一致的引号风格（默认为单引号） | 错误 | ✅ |
| `semi` | 要求或禁止使用分号 | 错误 | ✅ |
| `no-unused-vars` | 禁止出现未使用过的变量 | 警告 | ❌ |
| `comma-dangle` | 要求或禁止末尾逗号 | 警告 | ✅ |
| `arrow-parens` | 箭头函数参数括号风格 | 警告 | ✅ |
| `max-len` | 强制行的最大长度 | 警告 | 部分支持 |
| `eol-last` | 要求或禁止文件末尾保留一行空行 | 错误 | ✅ |

### 代码质量规则

代码质量规则帮助发现潜在的问题和错误，提高代码的健壮性。

| 规则 | 说明 | 严重级别 | 是否自动修复 |
|-----|------|---------|-------------|
| `no-console` | 禁用 console 方法 | 警告 | ❌ |
| `no-debugger` | 禁用 debugger | 错误 | ❌ |
| `no-alert` | 禁用 alert、confirm 和 prompt | 错误 | ❌ |
| `no-eval` | 禁用 eval() | 错误 | ❌ |
| `no-implied-eval` | 禁止使用类似 eval() 的方法 | 错误 | ❌ |
| `no-new-func` | 禁止对 Function 对象使用 new 操作符 | 错误 | ❌ |
| `no-return-assign` | 禁止在 return 语句中使用赋值语句 | 错误 | ❌ |
| `no-prototype-builtins` | 禁止直接使用 Object.prototypes 的内置属性 | 错误 | ❌ |
| `curly` | 强制所有控制语句使用一致的括号风格 | 错误 | ✅ |

### 导入/导出规则

导入/导出规则帮助管理模块依赖，确保导入导出的正确性。

| 规则 | 说明 | 严重级别 | 是否自动修复 |
|-----|------|---------|-------------|
| `import/order` | 强制导入的排序 | 警告 | ✅ |
| `import/first` | 确保所有导入都在文件顶部 | 错误 | ✅ |
| `import/no-mutable-exports` | 禁止导出可变的绑定 | 错误 | ❌ |
| `import/no-unresolved` | 确保导入的模块可以被解析 | 错误 | ❌ |
| `import/no-webpack-loader-syntax` | 禁止在导入中使用 Webpack 加载器语法 | 错误 | ❌ |

#### react/no-array-index-key 不支持 fix

不要使用 index 当 key，在 react 中使用 index 当 key 可能会造成一些问题，尤其是如果是希望改变列表的顺序。

```jsx
// 🔴 错误的用法
{list.map((item, index) => (
  <ListItem key={index} value={item} />
))}

// ✅ 正确的用法
{list.map((item) => (
  <ListItem key={item.id} value={item} />
))}
```

#### react/no-access-state-in-setstate 不支持 fix

不要在 this.setState 中使用 this.state

```jsx
// 🔴 错误的用法
this.setState({ value: this.state.value + 1 }); // 2
this.setState({ value: this.state.value + 1 }); // 2, 因为 setState 为异步所以还是 2 不是 3

// ✅ 正确的用法
this.setState((prevState) => ({ value: prevState.value + 1 }));
```

## 🔧 规则配置方法

### 规则严重性级别

ESLint 规则可以有三种严重性级别：

- `"off"` 或 `0` - 关闭规则
- `"warn"` 或 `1` - 将规则视为警告（不会导致退出代码非零）
- `"error"` 或 `2` - 将规则视为错误（退出代码为1，触发时）

### 自定义规则配置

您可以在配置文件中覆盖默认规则的级别：

```js
// eslint.config.mjs
import eslintPlugin from 'eslint-plugin-smart';

export default [
  ...eslintPlugin.configs.recommended,
  {
    rules: {
      // 覆盖规则级别
      'no-console': 'error', // 升级为错误
      'max-len': ['warn', { code: 100 }], // 修改配置选项
      'no-unused-vars': 'off', // 禁用规则
    }
  }
];
```

## 🌚 临时禁用规则

在某些情况下，你可能需要在特定行或区域临时禁用某些规则。ESLint 提供了注释指令来实现这一点：

### 禁用单行的规则

```js
// eslint-disable-next-line no-console
console.log('调试信息');
```

### 禁用下一个区域的规则

```js
/* eslint-disable no-console */
console.log('调试信息1');
console.log('调试信息2');
/* eslint-enable no-console */
```

### 禁用整个文件的规则

```js
/* eslint-disable */
// 此文件中所有规则都被禁用
/* eslint-enable */
```

::: warning 注意
虽然临时禁用规则有时是必要的，但应尽量避免滥用这一功能。对于需要频繁禁用的规则，考虑在配置文件中调整其级别。
:::
