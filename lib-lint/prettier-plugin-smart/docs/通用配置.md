# 通用配置

prettier-plugin-smart 提供了一套经过实践验证的通用 Prettier 配置，旨在确保公司内所有项目的代码风格一致性。这些配置作为默认值内置在插件中，可以被所有子项目直接引用和使用。

## 配置详情

以下是 prettier-plugin-smart 提供的通用配置项及其说明：

### 基础格式化选项

```js
{
  // 不使用分号
  semi: false,

  // 使用单引号
  singleQuote: true,

  // 所有可能的地方都添加尾随逗号
  trailingComma: 'all',

  // 每行最大宽度
  printWidth: 100,

  // 缩进宽度为2个空格
  tabWidth: 2,

  // 不使用制表符缩进
  useTabs: false,

  // 在对象字面量的括号之间添加空格
  bracketSpacing: true,

  // 箭头函数参数周围不添加括号
  arrowParens: 'avoid',

  // 使用 LF 作为行尾序列
  endOfLine: 'lf',
}
```

## 配置解释

### semi: false

不在语句末尾添加分号。这使代码更简洁，并符合现代 JavaScript 开发的趋势。

```js
// 格式化前
const name = 'John'
console.log(name)

// 格式化后
const name = 'John'
console.log(name)
```

### singleQuote: true

使用单引号而非双引号。这降低了输入时的复杂度，并使代码视觉上更清晰。

```js
// 格式化前
const message = 'Hello, world!'

// 格式化后
const message = 'Hello, world!'
```

### trailingComma: 'all'

在可能的地方添加尾随逗号，包括函数参数和调用。这可以使版本控制比较更清晰，并使添加新元素时的差异更小。

```js
// 格式化前
const obj = {
  a: 1,
  b: 2,
}

// 格式化后
const obj = {
  a: 1,
  b: 2,
}
```

### printWidth: 100

设置每行最大宽度为 100 个字符。这在保持代码可读性的同时，避免了过于频繁的换行，特别适合宽屏幕环境。

### tabWidth: 2

使用 2 个空格作为缩进。这是前端开发中常见的约定，可以保持代码紧凑而清晰。

### useTabs: false

使用空格而非制表符缩进，确保在不同编辑器中代码外观一致。

### bracketSpacing: true

在对象字面量的括号内添加空格。这提高了对象表达式的可读性。

```js
// 格式化前
const obj = { a: 1, b: 2 }

// 格式化后
const obj = { a: 1, b: 2 }
```

### arrowParens: 'avoid'

当箭头函数只有一个参数时，省略参数周围的括号。这使得简单的箭头函数更加简洁。

```js
// 格式化前
const double = (x) => x * 2

// 格式化后
const double = (x) => x * 2
```

### endOfLine: 'lf'

统一使用 LF 作为行尾序列，避免在不同操作系统间出现行尾混乱问题。

## 在子项目中使用

您可以在子项目中轻松引用这些通用配置，确保整个项目组的代码风格一致：

```js
// 子项目的 .prettierrc.js
const { defaultConfig } = require('prettier-plugin-smart')

module.exports = {
  ...defaultConfig,
  // 在这里添加或覆盖特定于项目的配置
}
```

## 不同框架下的配置扩展

通用配置是基础，您可以根据不同框架的特点进行扩展：

### React 项目

```js
// React项目的 .prettierrc.js
const { defaultConfig } = require('prettier-plugin-smart')

module.exports = {
  ...defaultConfig,
  // React特定配置
  jsxSingleQuote: false, // JSX中使用双引号
  importOrder: '^react,^@/components/,^@/hooks/,^@/utils/,^@/,^[./]',
}
```

### Vue 项目

```js
// Vue项目的 .prettierrc.js
const { defaultConfig } = require('prettier-plugin-smart')

module.exports = {
  ...defaultConfig,
  // Vue特定配置
  vueIndentScriptAndStyle: true,
  importOrder: '^vue,^@/components/,^@/composables/,^@/utils/,^@/api/,^[./]',
}
```

### NestJS 项目

```js
// NestJS项目的 .prettierrc.js
const { defaultConfig } = require('prettier-plugin-smart')

module.exports = {
  ...defaultConfig,
  // NestJS特定配置
  importOrder: '^@nestjs/,^@/modules/,^@/services/,^@/entities/,^@/dto/,^[./]',
}
```

## 配置冲突解决

如果您的项目有特殊需求，可以覆盖默认配置：

```js
// 自定义配置示例
const { defaultConfig } = require('prettier-plugin-smart')

module.exports = {
  ...defaultConfig,
  // 覆盖默认配置
  semi: true, // 使用分号
  printWidth: 80, // 缩短每行长度
  // 添加其他配置...
}
```

## 与 ESLint 集成

如果您同时使用 ESLint，建议添加 `eslint-config-prettier` 以避免规则冲突：

```js
// .eslintrc.js
module.exports = {
  extends: [
    // 其他扩展...
    'prettier', // 应放在最后，以确保覆盖冲突规则
  ],
  // 其他配置...
}
```

## 最佳实践

- 对于所有新项目，直接引用通用配置
- 对于现有项目，可以逐步迁移到通用配置
- 在 CI/CD 流程中添加格式检查，确保提交的代码符合规范
- 结合 Git 钩子（如 husky + lint-staged）在提交前自动格式化代码
