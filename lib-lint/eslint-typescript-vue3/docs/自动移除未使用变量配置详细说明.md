### 2. 未使用代码检测和自动删除

我们添加了全面的未使用代码检测和自动删除功能，帮助保持代码库的整洁。

#### 2.1 检测和自动删除范围

1. **未使用的导入**：

   - 自动删除未使用的导入语句
   - 自动删除部分导入中未使用的变量
   - 保持导入顺序和格式

2. **变量和参数**：

   - 检测未使用的变量
   - 检测未使用的函数参数
   - 支持通过 `_` 前缀忽略特定变量

3. **Vue 特定**：
   - 检测未使用的组件
   - 检测模板中未使用的变量
   - 检测未使用的 props 和 setup 变量

#### 2.2 配置示例

```js
{
  plugins: {
    'unused-imports': pluginUnusedImports
  },
  rules: {
    // 禁用原始的未使用变量检测
    'no-unused-vars': 'off',

    // TypeScript 的未使用变量检测
    '@typescript-eslint/no-unused-vars': ['error', {
      'vars': 'all',
      'args': 'after-used',
      'ignoreRestSiblings': true,
      'argsIgnorePattern': '^_',
      'varsIgnorePattern': '^_'
    }],

    // 自动删除未使用的导入
    'unused-imports/no-unused-imports': 'error',
    'unused-imports/no-unused-vars': [
      'error',
      {
        'vars': 'all',
        'varsIgnorePattern': '^_',
        'args': 'after-used',
        'argsIgnorePattern': '^_',
        'ignoreRestSiblings': true
      }
    ],

    // Vue 相关规则
    'vue/no-unused-components': ['error', {
      'ignoreWhenBindingPresent': true
    }],
    'vue/no-unused-vars': ['error', {
      'ignorePattern': '^_'
    }]
  }
}
```

#### 2.3 使用示例

```typescript
// 1. 自动删除未使用的导入
import { used, unused } from 'some-package' // unused 将被自动删除

// 2. 忽略特定变量
const _ignoredVar = 'This variable will not trigger unused warning'

// 3. Vue 组件中的使用
export default defineComponent({
  setup() {
    // 在模板中使用的变量不会被删除
    const message = ref('Hello')

    // 使用 _ 前缀忽略未使用的参数
    const handleClick = (_event: Event) => {
      console.log(message.value)
    }

    // 未使用的变量会被标记
    const unusedVar = ref('unused') // 将被标记为错误

    return { message, handleClick } // unusedVar 未返回，会被标记
  },
})
```

## 使用方法

### 1. 自动修复和删除

运行以下命令自动修复和删除未使用的代码：

```bash
npx eslint . --fix
```

### 2. 在 VSCode 中自动修复

在 VSCode 中，我们配置了保存时自动修复功能。配置如下：

```json
{
  "editor.codeActionsOnSave": {
    "source.fixAll.eslint": true,
    "source.organizeImports": true
  },
  "editor.formatOnSave": true,
  "eslint.validate": ["javascript", "javascriptreact", "typescript", "typescriptreact", "vue"],
  "eslint.format.enable": true,
  "eslint.run": "onSave"
}
```

### 3. 配置忽略

在某些特殊情况下，你可能需要忽略某些检查：

```typescript
// eslint-disable-next-line @typescript-eslint/no-unused-vars
const debugValue = 'This is for debugging'

/* eslint-disable unused-imports/no-unused-imports */
import { debug } from 'debug'
/* eslint-enable unused-imports/no-unused-imports */
```

## 注意事项

1. **自动删除安全性**：

   - 自动删除仅针对确定安全的情况（如未使用的导入）
   - 其他未使用的代码会被标记但不会自动删除
   - 建议在提交前检查自动删除的更改

2. **性能优化**：

   - 自动删除功能会在保存时触发
   - 大型项目中首次运行可能需要较长时间
   - 建议使用 Git 暂存更改后再运行完整检查

3. **Vue 特定注意事项**：

   - 模板中使用的变量不会被删除
   - `setup` 中返回的属性不会被删除
   - 组件的 props 不会被自动删除

4. **TypeScript 相关**：
   - 类型导入也会被自动清理
   - 仅类型使用的导入会被保留
   - 接口和类型定义的使用状态会被正确识别

## 常见问题

1. **Q: 自动删除误删了需要的代码怎么办？**  
   A: 可以使用 Git 恢复，或使用 `_` 前缀标记需要保留的变量。

2. **Q: 某些导入虽然未直接使用但需要保留，如何处理？**  
   A: 可以添加 `// eslint-disable-next-line unused-imports/no-unused-imports` 注释。

3. **Q: 为什么有些未使用的代码没有被自动删除？**  
   A: 出于安全考虑，自动删除仅限于导入语句，其他未使用的代码会被标记但需要手动删除。

4. **Q: VSCode 保存时没有自动删除未使用的代码？**  
   A: 检查 VSCode 设置中的 `editor.codeActionsOnSave` 配置是否正确，并确保安装了 ESLint 扩展。

## One

`dbaeumer.vscode-eslint` 和 `esbenp.prettier-vscode` 是两个不同的 VS Code 扩展，分别对应 **ESLint** 和 **Prettier** 代码检查与格式化工具的官方插件。它们的主要区别如下：

| 特性             | `dbaeumer.vscode-eslint`（ESLint）                   | `esbenp.prettier-vscode`（Prettier）       |
| ---------------- | ---------------------------------------------------- | ------------------------------------------ |
| **功能定位**     | 静态代码分析工具，用于检测代码中的潜在错误和风格问题 | 代码格式化工具，专注于统一代码风格         |
| **主要用途**     | 检查代码逻辑、语法、最佳实践等                       | 格式化代码，如缩进、空格、引号等样式统一   |
| **配置文件**     | `.eslintrc.js` / `.eslintrc.json` 等                 | `.prettierrc.js` / `.prettierrc.json` 等   |
| **是否修复代码** | 支持自动修复部分问题（通过 `eslint --fix`）          | 支持自动格式化所有问题                     |
| **适用场景**     | JavaScript、TypeScript、Vue、React 等                | JavaScript、TypeScript、CSS、HTML、JSON 等 |

## Two

`"source.fixAll.eslint": true` 和 `"source.fixAll.eslint": "explicit"` 是 VS Code 中 ESLint 插件在保存时自动修复代码行为的两种不同配置方式，区别如下：

| 特性                                     | `"source.fixAll.eslint": true`             | `"source.fixAll.eslint": "explicit"`                        |
| ---------------------------------------- | ------------------------------------------ | ----------------------------------------------------------- |
| **自动修复行为**                         | 自动尝试修复所有可修复的问题               | 仅修复用户显式选择（选中）的文件中的问题                    |
| **适用场景**                             | 所有 ESLint 可自动修复的问题               | 只有在手动触发“Fix all auto-fixable problems”命令时才会执行 |
| **与 `editor.codeActionsOnSave` 的关系** | 在保存时自动运行                           | 不会在保存时自动运行，需手动触发                            |
| **推荐使用场景**                         | 开发过程中希望保存时自动修复风格和简单错误 | 希望对修复行为进行更精细控制，避免自动修复影响代码逻辑      |

### 总结：

- ✅ 使用 `true`：适合大多数项目开发场景，保存即自动修复。
- ✅ 使用 `"explicit"`：适合需要人工确认或审查修复内容的场景。

你的当前配置是 `"source.fixAll.eslint": true`，表示在保存时会自动修复所有可修复的 ESLint 问题。
