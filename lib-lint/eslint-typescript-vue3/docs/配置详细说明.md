# ESLint TypeScript Vue3 配置详细说明

本文档详细说明了 ESLint 在 TypeScript 和 Vue3 项目中的配置内容，包括最新添加的 import 排序和未使用代码检测功能。

## 最新功能

### 1. Import 排序功能

为了保持代码的一致性和可读性，我们添加了自动 import 排序功能。

#### 1.1 功能特点

1. **分组排序**：imports 按以下顺序分组：

   - 内置模块 (node.js)
   - 外部模块 (npm packages)
   - 内部模块
   - 父目录模块
   - 兄弟目录模块
   - 当前目录模块
   - 对象导入
   - 类型导入

2. **分组间隔**：不同组之间自动添加空行
3. **字母排序**：每个分组内部按字母顺序排序
4. **重复检测**：自动检测并合并重复的导入

#### 1.2 配置示例

```js
rules: {
  'import/order': [
    'error',
    {
      'groups': ['builtin', 'external', 'internal', 'parent', 'sibling', 'index', 'object', 'type'],
      'newlines-between': 'always',
      'alphabetize': {
        'order': 'asc',
        'caseInsensitive': true
      }
    }
  ],
  'import/newline-after-import': ['error', { 'count': 1 }],
  'import/no-duplicates': 'error'
}
```

#### 1.3 使用示例

```typescript
// 正确的导入顺序
import fs from 'fs'
import path from 'path'

import axios from 'axios'
import { defineConfig } from 'vite'
import vue from 'vue'

import { AppConfig } from '@/config'
import { useStore } from '@/store'

import { UserService } from '../services'
import { formatDate } from '../utils'

import { Button } from './components'
import type { ButtonProps } from './types'
```

### 2. 未使用代码检测

我们添加了全面的未使用代码检测功能，帮助保持代码库的整洁。

#### 2.1 检测范围

1. **变量和参数**：

   - 未使用的变量
   - 未使用的函数参数
   - 未使用的私有类成员
   - 支持通过 `_` 前缀忽略特定变量

2. **无用代码**：

   - 不可达代码
   - 无用的表达式
   - 无用的返回语句
   - 无用的构造函数
   - 无用的计算属性键
   - 无用的重命名

3. **空代码**：

   - 空代码块（允许空 catch 块）
   - 空函数（允许空箭头函数和构造函数）
   - 空接口（允许单继承的空接口）

4. **Vue 特定**：
   - 未使用的组件
   - 模板中未使用的变量

#### 2.2 配置示例

```js
rules: {
  'no-unused-vars': 'off',
  '@typescript-eslint/no-unused-vars': ['error', {
    'vars': 'all',
    'args': 'after-used',
    'ignoreRestSiblings': true,
    'argsIgnorePattern': '^_',
    'varsIgnorePattern': '^_'
  }],
  'no-unused-private-class-members': 'error',
  'no-unreachable': 'error',
  'no-useless-return': 'error',
  'no-empty-function': ['error', {
    'allow': ['arrowFunctions', 'constructors']
  }],
  'vue/no-unused-components': ['error', {
    'ignoreWhenBindingPresent': true
  }]
}
```

#### 2.3 使用示例

```typescript
// 1. 忽略特定变量
const _ignoredVar = 'This variable will not trigger unused warning'

// 2. 允许的空箭头函数
const noop = () => {}

// 3. 允许的空 catch 块
try {
  doSomething()
} catch (e) {
  // 允许空的 catch 块
}

// 4. Vue 组件中的使用
export default defineComponent({
  setup() {
    // 在模板中使用的变量不会被标记为未使用
    const message = ref('Hello')

    // 使用 _ 前缀忽略未使用的参数
    const handleClick = (_event: Event) => {
      console.log(message.value)
    }

    return { message, handleClick }
  },
})
```

## 使用方法

### 1. 自动修复

运行以下命令自动修复可以自动修复的问题：

```bash
npx eslint . --fix
```

### 2. 仅检查

运行以下命令检查代码但不进行修复：

```bash
pnpm run lint
```

### 3. 配置忽略

在某些特殊情况下，你可能需要忽略某些检查：

```typescript
// eslint-disable-next-line @typescript-eslint/no-unused-vars
const debugValue = 'This is for debugging'

/* eslint-disable @typescript-eslint/no-unused-vars */
const test1 = 'test1'
const test2 = 'test2'
/* eslint-enable @typescript-eslint/no-unused-vars */
```

## 注意事项

1. **代码安全**：

   - 某些未使用代码的移除可能需要人工确认，因为它们可能影响程序行为
   - 特别注意副作用相关的代码删除

2. **性能考虑**：

   - 大型项目中使用 `--fix` 可能需要较长时间
   - 建议在提交前使用 `git add` 后执行修复

3. **Vue 特定注意事项**：

   - 模板中使用的变量不会被标记为未使用
   - `setup` 中返回的属性不会被标记为未使用
   - 组件的 props 默认不会被标记为未使用

4. **TypeScript 相关**：
   - 类型导入会被单独分组
   - 接口和类型定义的未使用检测可能需要特别配置

## 常见问题

1. **Q: 如何处理误报的未使用变量？**  
   A: 使用 `_` 前缀或添加适当的 eslint-disable 注释。

2. **Q: import 排序不生效怎么办？**  
   A: 确保安装了 `eslint-plugin-import` 并正确配置了 parser。

3. **Q: 自动修复可能带来的风险？**  
   A: 建议先提交当前更改，然后运行修复，以便在出现问题时可以回滚。
