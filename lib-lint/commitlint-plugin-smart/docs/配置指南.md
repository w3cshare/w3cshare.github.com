# 配置指南

## 基础配置

`commitlint-plugin-smart` 提供了开箱即用的配置，但你也可以根据项目需求进行自定义。

### 基本用法

```js
// .commitlintrc.js 或 .commitlintrc.mjs
import commitlintPluginSmart from 'commitlint-plugin-smart'

export default commitlintPluginSmart.defineConfig()
```

## MonoRepo 项目配置

对于 MonoRepo 项目，插件可以自动识别子项目作为可选作用域，极大地简化了配置过程：

```js
// .commitlintrc.js
import commitlintPluginSmart from 'commitlint-plugin-smart'

export default commitlintPluginSmart.defineConfig({
  isMongo: true, // 启用 MonoRepo 支持
})
```

启用 `isMongo` 后，插件会自动扫描项目中的子目录（如 `apps/*`、`packages/*`、`libs/*` 等），并将它们添加为可选的作用域。

## 自定义配置

### 自定义提交类型

你可以通过配置自定义提交类型：

```js
// .commitlintrc.js
import commitlintPluginSmart from 'commitlint-plugin-smart'

export default commitlintPluginSmart.defineConfig({
  rules: {
    // 自定义提交类型
    'type-enum': [
      2,
      'always',
      ['feat', 'fix', 'docs', 'custom-type'], // 添加自定义类型
    ],
  },
})
```

### 自定义作用域

你可以自定义作用域列表：

```js
// .commitlintrc.js
import commitlintPluginSmart from 'commitlint-plugin-smart'

export default commitlintPluginSmart.defineConfig({
  prompt: {
    scopes: ['auth', 'api', 'database', 'ui'], // 自定义作用域列表
  },
  rules: {
    'scope-enum': [2, 'always', ['auth', 'api', 'database', 'ui']],
  },
})
```

### 禁用 Emoji

如果你不需要在提交信息中使用 Emoji，可以禁用它：

```js
// .commitlintrc.js
import commitlintPluginSmart from 'commitlint-plugin-smart'

export default commitlintPluginSmart.defineConfig({
  prompt: {
    useEmoji: false, // 禁用 Emoji
  },
})
```

### 自定义提示信息

你可以自定义交互式提交过程中的提示信息：

```js
// .commitlintrc.js
import commitlintPluginSmart from 'commitlint-plugin-smart'

export default commitlintPluginSmart.defineConfig({
  prompt: {
    messages: {
      type: '请选择你要提交的更改类型:',
      scope: '请选择一个作用域 (可选):',
      subject: '请输入简短的提交描述:',
      // 其他提示信息...
    },
  },
})
```

## 规则配置

`commitlint-plugin-smart` 预设了一系列规则，你可以根据需要进行调整：

```js
// .commitlintrc.js
import commitlintPluginSmart from 'commitlint-plugin-smart'

export default commitlintPluginSmart.defineConfig({
  rules: {
    // 标题最大长度
    'header-max-length': [2, 'always', 120],

    // 是否允许空作用域
    'scope-empty': [0, 'never'],

    // 作用域格式（小写）
    'scope-case': [2, 'always', 'lower-case'],

    // 描述不能以.结尾
    'subject-full-stop': [2, 'never', '.'],

    // 描述格式要求
    'subject-case': [2, 'never', ['sentence-case', 'start-case', 'pascal-case', 'upper-case']],

    // 其他规则...
  },
})
```

## 完整配置示例

以下是一个包含多种自定义选项的完整配置示例：

```js
// .commitlintrc.js
import commitlintPluginSmart from 'commitlint-plugin-smart'

export default commitlintPluginSmart.defineConfig({
  isMongo: true, // 启用 MonoRepo 支持

  prompt: {
    // 自定义作用域
    scopes: ['auth', 'api', 'database', 'ui'],

    // 禁用 Emoji
    useEmoji: false,

    // 自定义提示信息
    messages: {
      type: '选择提交类型:',
      scope: '选择作用域 (可选):',
      subject: '填写简短描述:',
      body: '填写详细描述 (可选):',
      breaking: '列出破坏性变更 (可选):',
      footer: '列出关闭的 issue (可选):',
    },

    // 跳过某些问题
    skipQuestions: ['body', 'breaking', 'footer'],

    // 允许自定义作用域
    allowCustomScopes: true,
  },

  // 自定义规则
  rules: {
    'header-max-length': [2, 'always', 120],
    'scope-empty': [0, 'never'],
    'subject-case': [2, 'never', ['sentence-case', 'start-case', 'pascal-case', 'upper-case']],
  },
})
```

## 与其他工具集成

### 与 lint-staged 集成

```js
// .lintstagedrc.js
export default {
  '*.{js,jsx,ts,tsx}': ['eslint --fix', 'git add'],
  '*.{css,less,scss}': ['stylelint --fix', 'git add'],
  '*': ['commitlint --edit'],
}
```

### 与 GitHub Actions 集成

```yaml
# .github/workflows/commit-lint.yml
name: Lint Commit Messages
on: [pull_request]

jobs:
  commitlint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
        with:
          fetch-depth: 0
      - uses: actions/setup-node@v3
        with:
          node-version: '16'
      - run: npm install
      - name: Lint commit messages
        run: npx commitlint --from ${{ github.event.pull_request.base.sha }} --to ${{ github.event.pull_request.head.sha }} --verbose
```

## 常见问题

### 如何在已有项目中引入规范？

对于已有项目，可以逐步引入提交规范：

1. 先安装和配置 `commitlint-plugin-smart`
2. 在团队中宣导新的提交规范
3. 可以先不强制执行规则，设置为警告级别
4. 待团队适应后，再调整为错误级别

### 如何处理特殊的提交需求？

如果有特殊的提交需求，可以：

1. 自定义提交类型和作用域
2. 调整规则的严格程度
3. 在特殊情况下使用 `--no-verify` 跳过检查（不推荐经常使用）

### 提交信息格式说明

标准的提交信息格式为：

```
<type>(<scope>): <subject>
<BLANK LINE>
<body>
<BLANK LINE>
<footer>
```

- **type**: 提交类型，如 feat、fix 等
- **scope**: 可选，表示影响范围
- **subject**: 简短描述
- **body**: 可选，详细描述
- **footer**: 可选，关闭 issue 等信息
